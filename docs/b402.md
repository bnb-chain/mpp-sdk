# B402 integration

B402 is available through two protocol Adapters backed by one Provider Module.

| Path              | Package                   | Methods                 |
| ----------------- | ------------------------- | ----------------------- |
| Official x402     | `@bnb-chain/b402`         | EIP-3009, Permit2 Exact |
| MPP `b402/charge` | `@bnb-chain/mpp-b402`     | EIP-3009, Permit2 Exact |
| mppx `evm/charge` | `createB402Facilitator()` | EIP-3009 only           |

Permit2 Upto is intentionally unsupported. The Binance facilitator is hosted;
this workspace implements its authenticated client and protocol Adapters, not
the facilitator backend.

## Package entry points

| Entry point                  | Runtime        | Purpose                                                 |
| ---------------------------- | -------------- | ------------------------------------------------------- |
| `@bnb-chain/b402`            | browser/server | Provider wire types and proof primitives.               |
| `@bnb-chain/b402/client`     | browser/server | Official x402 buyer Scheme and allowance policy.        |
| `@bnb-chain/b402/server`     | Node           | RSA client, cache, settlement and x402 server Adapters. |
| `@bnb-chain/mpp-b402`        | browser/server | Shared MPP `b402/charge` Method.                        |
| `@bnb-chain/mpp-b402/client` | browser/server | MPP wallet Adapter.                                     |
| `@bnb-chain/mpp-b402/server` | Node           | MPP merchant and mppx facilitator Adapters.             |

## Direct official x402

Install:

```bash
pnpm add @bnb-chain/b402 @x402/core @x402/fetch viem
```

Merchant Provider setup:

```ts
import { x402ResourceServer } from '@x402/core/server'
import { B402Client, B402ExactServerScheme, B402FacilitatorClient } from '@bnb-chain/b402/server'

const transport = B402Client.fromEnv()
if (!transport) throw new Error('B402 is not configured')

const facilitator = new B402FacilitatorClient({
  client: transport,
  onSettlementUnknown: queueForReconciliation,
})

const payments = new x402ResourceServer(facilitator).register(
  'eip155:*',
  new B402ExactServerScheme({ facilitator }),
)
await payments.initialize()
```

Each protected route selects its B402 transfer method through server-owned
`extra` values. Atomic-unit prices work without a currency registry:

```ts
const requirements = await payments.buildPaymentRequirements({
  scheme: 'exact',
  network: 'eip155:56',
  payTo: '0xYourRegisteredPayout',
  price: { asset: '0xToken', amount: '1000000' },
  extra: {
    assetTransferMethod: 'permit2-exact', // or 'eip3009'
    name: 'Token EIP-712 Domain Name',
    version: '1',
  },
})
```

For decimal or dollar prices, pass a `moneyParser` to
`B402ExactServerScheme`. The normal x402 Hono/Express/Next Adapter can own the
HTTP route lifecycle around this resource server.

Buyer:

```ts
import { x402Client } from '@x402/core/client'
import { B402ExactClientScheme } from '@bnb-chain/b402/client'

const payments = new x402Client().register(
  'eip155:*',
  new B402ExactClientScheme({
    account: walletAccount,
    permit2Allowance: readPermit2Allowance,
    trustedSpenders: {
      'eip155:56': ['0xAuditedB402ExactProxy'],
    },
  }),
)
```

Pass that client to `@x402/fetch`, `@x402/axios`, or another official transport
Adapter. The SDK creates standard v2 `PAYMENT-SIGNATURE` payloads; it does not
implement a second fetch loop.

## MPP-native B402

Install:

```bash
pnpm add @bnb-chain/b402 @bnb-chain/mpp-b402 mppx viem
```

Merchant:

```ts
import { B402Client } from '@bnb-chain/b402/server'
import { b402 } from '@bnb-chain/mpp-b402/server'
import { Mppx } from 'mppx/server'

const client = B402Client.fromEnv()!
const method = await b402.charge({
  client,
  network: 'eip155:56',
  currency: {
    address: '0xToken',
    decimals: 18,
    name: 'Token EIP-712 Domain Name',
    version: '1',
  },
  recipient: '0xYourRegisteredPayout',
  onSettlementUnknown: queueForReconciliation,
})

const payments = Mppx.create({ methods: [method], secretKey })
const route = payments.b402.charge({
  amount: '0.01',
  transferMethod: 'permit2-exact', // or 'eip3009'
})
```

Buyer:

```ts
import { CURATED_B402_SPENDERS } from '@bnb-chain/b402/client'
import { b402 } from '@bnb-chain/mpp-b402/client'
import { Mppx } from 'mppx/client'

const method = b402.charge({
  account: walletAccount,
  allowedNetworks: ['eip155:56'],
  maxAmount: '1',
  permit2Allowance: readPermit2Allowance,
  trustedSpenders: {
    'eip155:56': [CURATED_B402_SPENDERS['eip155:56']!.exact],
  },
})

const payments = Mppx.create({
  methods: [method],
  orderChallenges: method.prefer(['permit2-exact', 'eip3009'], {
    onMissingAllowance: 'fallback',
  }),
})
```

MPP credentials use `keccak256(challenge.id || challenge.realm)` as their
nonce. Direct x402 proofs use fresh protocol-native nonces. Neither Adapter
translates the other protocol's signed witness.

## Standard mppx EIP-3009 compatibility

`createB402Facilitator()` remains a thin Adapter for mppx's standard
`evm/charge` facilitator Seam:

```ts
import { B402Client } from '@bnb-chain/b402/server'
import { createB402Facilitator } from '@bnb-chain/mpp-b402/server'

const facilitator = createB402Facilitator({
  client: B402Client.fromEnv()!,
  onSettlementUnknown: queueForReconciliation,
})
```

It is EIP-3009-only because generic MPP Permit2 and B402 Permit2 Exact bind
different spenders and witnesses.

## Settlement invariants

Before network calls, the Implementation pins network, asset, amount, payout,
method, EIP-712 domain, signer and Permit2 spender; recovers the payer locally;
and reconstructs the B402 request. Buyer-provided resource or extension objects
are never forwarded. Bazaar metadata can only come from merchant configuration.

Settlement outcomes are classified as:

- success: transaction hash, amount, network and payer all match;
- definitive rejection: `success: false` with an empty transaction;
- unknown: transaction evidence on failure, transport/parser failure, or an
  incomplete/mismatched success.

Unknown settlement raises `B402SettlementUnknownError` and calls the configured
handler with the exact reconstructed request. The merchant owns durable order
state, fulfillment idempotency and on-chain reconciliation.

## Credentials

`B402Client.fromEnv()` reads an all-or-nothing group:

```text
B402_BASE_URL
B402_CLIENT_ID
B402_ACCESS_TOKEN
B402_PRIVATE_KEY
```

The key is the RSA request-signing key issued during onboarding, not an EVM
private key.
